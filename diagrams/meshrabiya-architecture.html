Key Architectural Decisions

1. CoreGossipBroadcastService Access Pattern

Decision: Access via VirtualNode property

private val coreGossipBroadcastService = virtualNode.coreGossipBroadcastService

Instantiated in VirtualNode constructor, no dependency injection in service constructors needed.

2. Replica Count Propagation Model

Decision: Start at 0, increment during transfer (not after storage)

Flow: Client(0) → StorageA stores(0) → replicates(1) → StorageB stores(1) → replicates(2) → StorageC stores(2) → replicates(3) → StorageD receives(3) → STOP (3≥3)

No synchronization needed - trust propagation model with independent increments.

3. Replication Retry Strategy

Decision: Mirror storage node request retry pattern

Use MeshrabiyaConstants.getTimeoutMs(), getMaxRetries()

Retry delay: 10 seconds (RETRY_DELAY_MS = 10000L)

4. Client/Server Separation

Critical: Never mix client and server logic in same function

  • storeFile() - Client side only (request preparation, broadcast)
  • handleIncomingChunkStorage() - Storage node side (receive, store, replicate)
  • processTaskRequest() - Client side only
  • handleIncomingTaskRequest() - Compute node side
